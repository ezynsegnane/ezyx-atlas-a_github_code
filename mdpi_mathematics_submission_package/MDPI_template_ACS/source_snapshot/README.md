# Source Snapshot

This directory bundles the code and environment snapshot needed to inspect the
training, analysis, and figure-generation pipeline that produced the archived
manuscript artifacts.

## Included

- Core training and analysis sources from the project root.
- Figure-generation and robustness-evaluation scripts from `scripts/`.
- `requirements.txt` and `environment.yml`.
- Project-level metadata files such as `LICENSE`, `CITATION.cff`, and the root
  package manifest.

Some copied project-level metadata files, especially the historical root
`PACKAGE_MANIFEST.md`, describe the original release inventory rather than the
reduced submission-package payload. The authoritative inventory for the present
submission package is the `MDPI_template_ACS` folder itself together with its
local `README.md`, `VERSION`, and `CHANGELOG.md`.

The archived training source preserves the software-side determinism settings
used by the original pipeline, including
`torch.backends.cudnn.deterministic=True` and
`torch.backends.cudnn.benchmark=False`. Exact GPU/CUDA identifiers were not
retained in the run logs and therefore cannot be reconstructed here.

## Execution note

The archived Python entry points use local imports such as
`from eznx_loader_v2 import ...` and `from eznx_model_v5 import ...`.
When inspecting or re-running the snapshot, launch scripts from this
`source_snapshot/` directory (or add this directory to `PYTHONPATH`) so that
those local imports resolve consistently.

## Figure 2 — validation trajectory (mean ± SD)

Figure 2 (`figures/fig2_training_curves.pdf`) is generated by
`scripts/generate_fig2_m4.py`, **not** by
`scripts/render_manuscript_result_figures.py`.

`generate_fig2_m4.py` reads the 30 seed-level JSON files from
`artifacts/seed_json/` and plots the mean ± 1 SD validation AUC trajectory
across seeds for each variant.  To regenerate the figure from within the
package, run:

```sh
python scripts/generate_fig2_m4.py \
    --seed_json_dir artifacts/seed_json \
    --out_dir figures
```

`render_manuscript_result_figures.py` generates the remaining manuscript
figures (Fig. 3–6) and requires access to the full project workspace
(see path notes below).

## Working-index path

The PTB-XL metadata index (`index_complete.parquet`) is built by
`scripts/build_index.py`, which writes to `data/index_complete.parquet`
relative to the project root.  All archived scripts now use this location
as their default:

- `atlas_a_v5_multiseed.py` → `data/index_complete.parquet`
- `run_multiseed_experiments.py` → `data/index_complete.parquet`
- `scripts/evaluate_missingness_robustness.py` → `data/index_complete.parquet`

You can override the path at run time with the `--index_path` CLI flag or the
`EZNX_INDEX_PATH` environment variable.

## Path dependencies in archived scripts

Several scripts in `scripts/` and the root-level entry points use default
paths that are relative to the **original project workspace root**, not to
this package directory.  In particular:

- `render_manuscript_result_figures.py` defaults to
  `PROJECT_ROOT / "runs_test"` for model checkpoint discovery and
  `PROJECT_ROOT / "submission_artifacts_en"` for output artifacts.
  Neither directory exists inside this package.
- `analyze_multiseed_results.py` defaults to
  `PROJECT_ROOT / "results" / "seed_json"` for its input JSON directory.

Package-local equivalents for the statistical inputs are available in
`artifacts/`:

| External default path              | Package-local equivalent          |
|------------------------------------|-----------------------------------|
| `results/seed_json/*.json`         | `artifacts/seed_json/*.json`      |
| `runs_extended/*/results_ext_*.json` | `artifacts/extended_runs/*.json`|
| `statistical_analysis_full.json`   | `artifacts/statistical_analysis_full.json` |

These scripts are archived for code inspection only.  Full re-execution
requires providing the PTB-XL data root and overriding the default paths
via command-line arguments.

## Seed-level JSON layout and `analyze_multiseed_results.py`

`analyze_multiseed_results.py` discovers results by scanning for
**subdirectories** named `ATLAS_A_v5_<variant>_seed<N>` inside the given
`--runs-dir`, then reads `results_<variant>_seed<N>.json` from within each
subdirectory.

The seed-level JSON files archived in `artifacts/seed_json/` use a **flat
layout** (`results_demo+anthro_seed2024.json`, etc.) that does not match this
subdirectory convention.  Pointing `analyze_multiseed_results.py` directly at
`artifacts/seed_json/` will therefore find zero results.

To inspect the statistical outputs without restructuring the files:
- Use `artifacts/statistical_analysis_full.json` directly — it contains the
  pre-computed aggregate metrics, paired comparisons, BH-FDR results, and power
  analysis for all 30 runs.
- To re-run `analyze_multiseed_results.py` from scratch, recreate the original
  subdirectory layout:
  ```
  runs/ATLAS_A_v5_none_seed2024/results_none_seed2024.json
  runs/ATLAS_A_v5_demo_seed2024/results_demo_seed2024.json
  ...
  ```

## Not included

- Raw ECG signal files from PTB-XL (available at
  https://physionet.org/content/ptb-xl/1.0.3/).
- Patient-level prediction arrays for all 30 runs (documented as
  Limitation 3 in the manuscript).
- PyTorch model checkpoints (excluded for storage reasons; checkpoints
  for the 5 extended runs are in `runs_extended/` in the project workspace).

The goal is package-local inspectability, not a second full copy of the entire
project workspace.

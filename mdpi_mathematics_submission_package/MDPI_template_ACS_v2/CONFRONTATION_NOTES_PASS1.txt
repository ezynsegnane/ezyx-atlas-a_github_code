─────────────────────────────────────────────────────────────────
[CF1] CRITICAL — §4.5 Residual injection: W_sum formula is WRONG
─────────────────────────────────────────────────────────────────

MANUSCRIPT (§4.5, Eq. hts):
  h_ts = h_ts1 + 0.10 × q_meta × W_sum × h_m
  W_sum = W_res + W_addon
  W_res, W_addon ∈ R^{1024×128}, both ← 0 at init.
  "The two projections are independently zero-initialised,
   making both injection paths neutral at initialisation."
  "the effective attenuation of each residual path is q_meta²"

MANUSCRIPT (Figure 1 caption):
  "Two parallel zero-initialised 1024×128 projections
   (W_res, W_addon) softly bias the ECG embedding via
   residual injection (Eq. hts)"

MANUSCRIPT (§4.8 parameter budget):
  "0.26 M in the two metadata-to-ECG residual projections
   (W_res and W_addon, each R^{1024×128}, both zero-initialised)"

CODE (eznx_model_v5.py, forward()):
  Standard mode (all 60 Group A runs):
    h_ts = h_ts + 0.10 * self.ts_meta_residual(h_m) * meta_quality
  — only ts_meta_residual (W_res) is used.

  E3 additive ablation (Group E only):
    h_ts_aug = h_ts + self.ts_meta_addon(h_m)
  — only ts_meta_addon (W_addon) is used, WITHOUT q_meta scaling.

  W_res + W_addon are NEVER combined in any mode.
  ts_meta_addon receives ZERO gradient in standard mode (never
  called in forward()). It stays at zero throughout training.

CONCLUSION:
  The manuscript's "W_sum = W_res + W_addon" formula is FACTUALLY
  INCORRECT for the standard architecture. W_addon is an E3-only
  ablation path, never combined with W_res.

FIX REQUIRED:
  §4.5: Replace the W_sum equation with the single-projection form.
  Add a note that W_addon exists for E3 only.
  Figure 1 caption: correct "two parallel projections" to "one
  residual projection (W_res); W_addon instantiated for E3 only".
  §4.8: Clarify that W_res is active in standard mode; W_addon
  is only active during E3 ablation runs (but both count toward
  the 0.26 M parameter budget since both exist in the model).

─────────────────────────────────────────────────────────────────
[CF2] SIGNIFICANT — §3.4 Pos-weights formula describes
       normalization that is NOT implemented in the code
─────────────────────────────────────────────────────────────────

MANUSCRIPT (§3.4, Eq. posweights):
  w_c^+ = ((1-f_c)/f_c) / ((1-f_NORM)/f_NORM)
  "Normalising to NORM ... keeping the NORM weight at unity."
  "The resulting weight vector [w_NORM, w_MI, w_STTC, w_CD, w_HYP]
   ≈ [1.0, 2.98, 3.16, 3.46, 7.22] is computed once on folds 1–8
   and held fixed across all runs."

CODE (atlas_a_v5_multiseed_v2.py, compute_pos_weights()):
  raw_weights = neg / np.maximum(pos, 1)
  weights = np.clip(raw_weights, 0.5, 30.0)
  — NO normalization to NORM.

ANALYSIS PLAN (analysis_plan.md §4, item 4):
  "pos_weights: dynamic, computed per run — neg_j / pos_j per class,
   clipped to [0.5, 30.0], computed from training folds only."

ACTUAL TRAINING LOG (results_ATLAS_A_v5_demo_seed2024.json):
  "pos_weights": [1.2930, 2.9776, 3.1610, 3.4582, 7.2199]

  NORM actual weight = 1.2930 (NOT 1.0 as stated in manuscript).
  MI, STTC, CD, HYP values closely match the manuscript (rounded),
  because they happen to be near the raw neg/pos values.

SPECIFIC ERRORS:
  1. Formula wrong: code uses raw neg/pos + clip; no NORM division.
  2. NORM weight wrong: 1.29 (actual) vs 1.0 (claimed).
  3. "held fixed across all runs" is WRONG: the code recomputes
     per run from training folds. For Group F (different fold
     assignments), the weights differ from Groups A–E. For Groups
     A–E all using folds 1–8 for training, the values are
     numerically identical run-to-run but NOT "computed once."

FIX REQUIRED:
  Update §3.4 Eq. (posweights) to the actual formula:
    w_c^+ = clip(neg_c / pos_c, 0.5, 30.0)
  Update the weight vector to ≈ [1.29, 2.98, 3.16, 3.46, 7.22].
  Remove "normalising to NORM" text.
  Replace "computed once on folds 1–8 and held fixed" with
    "computed dynamically at the start of each run from the
     training folds."

[CF3] OBSERVATION — Group D: 20 seeds trained, only 10 analyzed
─────────────────────────────────────────────────────────────────

MANUSCRIPT (§5.4):
  "Group D (exploratory, 20 runs). Augmentation ablation: standard
   (aug, reference) vs. no-augmentation (noaug), 10 seeds each."

  SEEDS_20 = list(range(2024, 2044))   # 20 seeds

  → 20 noaug runs trained (seeds 2024–2043).

ANALYSIS SCRIPT (analyze_multiseed_v2.py):
  aug_vals   = collect_metric(runs_dir, "demo+anthro", SEEDS_10)
  noaug_vals = collect_metric(runs_dir, "demo+anthro", SEEDS_10, no_aug=True)
  → Analysis uses only SEEDS_10 (seeds 2024–2033, first 10).

  The manuscript correctly reports n=10 (matching the analysis
  script). However, 20 noaug seeds were trained but only 10 were
  used in the analysis. The extra 10 noaug runs (seeds 2034–2043)
  are unused. This is suboptimal but not a factual error in the
  manuscript.

  No manuscript fix required. Add a remark acknowledging this
  in the confrontation notes for transparency.

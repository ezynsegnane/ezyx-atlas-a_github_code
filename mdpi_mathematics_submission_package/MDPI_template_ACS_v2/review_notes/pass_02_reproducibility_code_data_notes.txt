REVUE PASS 02 - REPRODUCTIBILITE, CODE, DONNEES, ARTEFACTS
Manuscrit: main_en.tex / main_en.pdf
Code inspecte: source_snapshot et racine du depot ezyx-atlas-a_gihub
Date de revue: 2026-05-19

Objectif de la passe:
Verifier si un reviewer peut reproduire ou auditer les resultats a partir du package, du depot public et des artefacts results/.

R201 - Alignement package-source vs code de campagne
Severite: MAJEURE.
Observation: le source_snapshot contient eznx_loader_v2.py, eznx_model_v5.py, requirements.txt et le script de rendu des figures, mais pas tout le pipeline d'entrainement/analyse.
Risque reviewer: le snapshot peut etre juge insuffisant pour reproduire les 250 runs.
Action: inclure les scripts exacts de training/orchestration/statistics/index construction, ou declarer clairement que le snapshot est partiel et que le depot public/tag est la source executable complete.

R202 - Divergence de scaling ECG dans le loader snapshot
Severite: MAJEURE.
Observation: le loader dans source_snapshot divise le signal par 5.0, alors que le loader racine ne le fait pas; la division est appliquee dans le collate/training script racine.
Risque reviewer: si quelqu'un combine snapshot loader et training script, le signal peut etre doublement scale. Meme si les runs historiques sont corrects, le package soumis ne represente pas exactement le code d'execution.
Action: synchroniser source_snapshot avec le commit exact des runs, ou ajouter un README explicite indiquant ou se trouve la normalisation et quel script doit etre utilise.

R203 - Commit et provenance des runs
Severite: MODEREE.
Observation: les JSON de runs indiquent un git_sha de campagne et un SHA-256 du plan d'analyse. Le manuscrit mentionne aussi un commit de plan.
Risque reviewer: confusion entre commit du plan, commit du code execute et commit/tag du depot public.
Action: ajouter une table "provenance" avec: plan commit, run code commit, artifacts release/tag, date de generation.

R204 - Artefacts results/ obsoletes
Severite: MAJEURE.
Observation: certains rapports markdown dans results/ parlent encore de n=10 seeds et de valeurs qui ne correspondent plus au manuscrit n=20.
Risque reviewer: accusation de reporting incoherent ou selective updating.
Action: regenerer ou retirer les fichiers obsoletes; ajouter un README results/ distinguant current vs deprecated.

R205 - Protocol markdown incoherent
Severite: MAJEURE.
Observation: le protocole public inspecte contient encore des formulations sur blend weights choisis en validation et tie-breakers favorisant Delta_meta, alors que le manuscrit affirme w*=1.0 fixe et checkpoint par val macro-AUC.
Risque reviewer: soupcon que le protocole a change apres observation des resultats.
Action: corriger le protocole public, historiser l'ancienne version si necessaire, et faire correspondre texte/code.

R206 - Plan pre-declare non entierement reporte
Severite: MAJEURE.
Observation: le plan public annonce des baselines classiques, controles mask-only/shuffle, AUPRC, calibration et subgroups; le manuscrit ne les reporte pas tous.
Risque reviewer: selective reporting.
Action: ajouter une section supplementaire "Pre-specified analyses not in main text" avec resultats ou justification dattee.

R207 - Baselines classiques
Severite: MAJEURE.
Observation: logistic regression et XGBoost sont annonces comme baselines toujours reportees dans le plan public.
Risque reviewer: demander pourquoi elles manquent.
Action: les reporter en supplement ou corriger le plan si elles etaient hors scope avant execution.

R208 - Metadata controls
Severite: MAJEURE.
Observation: les controles value-shuffle et mask-only sont essentiels pour distinguer contenu physiologique vs signal de presence.
Risque reviewer: l'effet metadata peut etre attribue a missingness/fold artifacts.
Action: inclure ces controles, au moins pour Group A.

R209 - Calibration et AUPRC
Severite: MODEREE.
Observation: le plan mentionne AUPRC, Brier/ECE et subgroup AUC. Le manuscrit reste presque exclusivement macro-AUC.
Risque reviewer: insuffisant pour claims de robustesse/deploiement.
Action: ajouter en supplement, ou dire explicitement que les conclusions sont uniquement discrimination macro-AUC.

R210 - Outputs patient-level non archives
Severite: MAJEURE.
Observation: data availability dit que les arrays de probabilites patient-level ne sont pas archives.
Risque reviewer: impossible de verifier calibration, fairness, seuils, erreurs, bootstrap alternatif ou analyses independantes.
Action: archiver predictions/labels/ids/splits par run, ou un format anonymise suffisant.

R211 - Group F et construction index metadata
Severite: CRITIQUE.
Observation: l'index metadata est z-score/impute une fois avec train_mask folds 1-8. Dans les splits alternatifs, les folds test/validation peuvent etre inclus dans le scaler et des folds train alternatifs exclus.
Risque reviewer: fuite de donnees et comparaison fold-level compromise.
Action: reconstruire l'index pour chaque split Group F ou retirer Group F des conclusions.

R212 - Group F, effet sur conclusion
Severite: CRITIQUE.
Observation: Group F teste seulement demo+anthro; il ne teste pas none/demo sur les memes splits alternatifs.
Risque reviewer: impossible de conclure que le gain metadata se generalise aux autres folds; on observe seulement le score absolu d'un modele.
Action: recalculer none/demo/demo+anthro pour chaque split, avec normalisation split-specific, ou reduire le claim.

R213 - Reproductibilite des seeds
Severite: MODEREE.
Observation: le design seed-wise est fort, mais le manuscrit doit garantir seeds identiques et deterministic settings.
Risque reviewer: variabilite hardware/threads CPU non controlee.
Action: documenter torch deterministic flags, threads, versions et seed propagation.

R214 - Requirements
Severite: MODEREE.
Observation: requirements snapshot peut ne pas figer toutes les dependances exactes observees dans les JSON hardware.
Risque reviewer: environnement non reproductible.
Action: fournir environment.yml ou requirements lock avec versions exactes torch/scipy/sklearn/wfdb.

R217 - URL GitHub

Severite: MINEURE.
Observation: certains scripts mentionnent "Scientific Reports" ou "GPU runs" alors que le manuscrit est MDPI Mathematics et CPU-only.
Risque reviewer: impression de package recycle ou non nettoye.
Action: nettoyer docstrings et README.

R219 - Donnees externes PhysioNet
Severite: MINEURE.
Observation: PTB-XL est public et citable. L'access date "2024" est probablement a actualiser.
Action: mettre la date d'acces reelle ou "accessed on 19 May 2026" si c'est la date verifiee.

R220 - Conclusion de la passe 02
La reproductibilite est le point le plus vulnerable. Le coeur statistique Group A peut etre defendu, mais le package public doit etre nettoye avant soumission: snapshot exact, artefacts coherents, predictions archivees, et Group F recalcule ou retire.

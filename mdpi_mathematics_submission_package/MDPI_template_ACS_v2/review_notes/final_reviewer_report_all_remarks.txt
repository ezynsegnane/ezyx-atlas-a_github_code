Remarques critiques a corriger avant soumission

1. Incoherence missingness n=10 vs n=20
- L351 dit que la courbe empirique de masking est evaluee sur demo+anthro avec 10 seeds (2024-2033).
- L513 confirme que le public missingness report couvre demo+anthro seulement, 10 seeds.
- L704, caption Figure 4, dit "across 20 seeds".
- `source_snapshot/scripts/render_figures_v2.py` ligne 315 ecrit aussi "n = 20 seeds" pour Fig 4.
- C'est une attaque directe et facile. Corriger la caption, l'axe, le texte et le rapport public. Si les none/demo traces viennent de 20 seeds mais demo+anthro masking de 10, le dire explicitement.

2. Code snapshot incoherent avec preprocessing annonce
- L169 dit que les signaux ECG sont divises par 5.0 avant le modele.
- `source_snapshot/eznx_loader_v2.py` lit WFDB, pad/truncate, transpose, et retourne le tensor sans division par 5.0.
- Si la division est faite ailleurs, le script manque. Sinon le manuscrit est faux.
- Le manuscrit decrit aussi filtering physiologique, median imputation, standardisation; le loader lit des colonnes deja precomputees. Fournir le script de creation de l'index ou corriger la description.

3. Supplementary/release snapshot non soutenu localement
- L503 affirme que le release snapshot bundle contient Table S1, all 250 seed-level JSON outputs, CSV/Markdown statistical tables, dataset-integrity notes, environment files, scripts.
- Dans le dossier local, `artifacts` est vide et les JSON/stat tables ne sont pas presents.
- L513 dit que le depot GitHub public contient tout; cela peut etre vrai, mais le package local ne le demontre pas.
- Corriger la formulation ou ajouter les artefacts promis.

4. DOI Holloway2026 probablement incorrect
- bibliography.bib donne `10.1007/978-3-031-87568-3`.
- Spot-check externe trouve pour le chapitre "Evaluation of Raw Signal and Feature-Based Deep Learning Models for Multi-Label ECG Diagnosis on PTB-XL" le DOI `10.1007/978-3-032-11442-6_36`, pages 458-464.
- Corriger reference avant soumission.

5. Hyperref/PDF metadata
- main_en.log contient de nombreux hyperref warnings a la ligne 81.
- `pdfinfo` montre un Subject PDF enorme avec math mal converti et un Author avec mojibake pour Peluffo-Ordonez.
- Les metadonnees PDF doivent etre nettoyees avec des strings simples sans math/LaTeX et un encodage correct.

Remarques majeures de methodologie/statistiques

6. "Pre-specified" et "confirmatory" doivent etre prouves
- Le manuscrit repete "pre-declared/pre-specified 3-test family".
- Sans plan date, commit, preregistration, supplement S1 inclus, ou notebook verrouille, un reviewer peut dire que cette famille a ete definie apres coup.
- Ajouter Table S1 et une note de provenance: date, hash, chemin, ou archive.

7. Les p-values exploratoires sont trop valorisees
- Abstract L75: "Exploratory groups confirm..." est trop fort.
- Discussion/conclusion: Groups B/C/E "confirm architectural robustness" alors qu'ils sont n=10, uncorrected, exploratory.
- Group D p=0.002 est interessant mais non corrige dans l'ensemble exploratory. Dire "motivates confirmatory testing" plutot que conclusion ferme.

8. Group F ne prouve pas la generalisation du gain metadata
- Group F teste seulement demo+anthro sur quatre folds alternatifs, 5 seeds chacun.
- Il ne teste pas none/demo sur ces folds, donc ne montre pas que +0.0007 ou +0.0019 generalisent.
- Reformuler: "fold 10 had lower absolute demo+anthro AUC than the four tested alternative folds." Eviter "confirmatory generalisation" et "conservatively difficult split" sans nuance.

9. Unite d'inference = seed, pas patient
- Le papier est clair sur seed-level inference, mais les effets sont tres petits.
- Ajouter pres des resultats: CIs quantify run-to-run variability, not patient-level uncertainty.
- Patient-level probability arrays non archivees: cela limite verification independante, DeLong, calibration, threshold analysis, subgroup analysis.

10. Exact Wilcoxon implementation
- Preciser zero_method/ties/exact method/software version.
- Donner exact raw p et BH p plutot que `approx` ou `<` dans les tables supplementaires.
- La phrase sur p minimum `2/2^20` est correcte seulement sous conditions sans ties; garder prudence.

11. Label protocol vs canonical benchmark
- Le loader declare un superclass positive si tout code SCP associe existe, sans threshold de likelihood.
- PTB-XL `scp_codes` contient des likelihoods; un reviewer comparera cela au protocole Strodthoff.
- Ajouter une justification et/ou une verification que les labels reproduisent exactement le benchmark super-diagnostic canonique.

12. q_meta et "quality-gated" claims
- Le manuscrit reconnait que `q_meta` sature a 1 lorsque age/sex sont presents.
- Donc la degradation sous anthropometric masking est surtout due aux missingness indicators + meta-dropout, pas a une quality score interpolation.
- Attenuer "quality-gated fusion" dans abstract/title/captions ou expliquer que q_meta sert surtout de hard gate none vs metadata.

13. "ECG-only" terminology
- `none` est une architecture multimodale metadata-disabled avec fused head/gate recevant zeros, pas un pur ECG-only backbone standard.
- Utiliser "metadata-disabled reference" quand la precision compte.
- Le fused vs ECG auxiliary head gap ne doit pas etre presente comme comparaison a un modele ECG independant.

14. E8 interpretation
- E8 trainmask est un train/inference distribution shift extreme.
- Il montre que ce modele ne peut pas recevoir metadata a inference si entraine zero-meta, mais ne prouve pas une regle generale sur toutes architectures.
- Garder le terme "negative control".

15. Clinical utility non demontree
- Les gains AUC sont petits et aucune calibration, decision curve, net benefit, external cohort, subgroup fairness ou reclassification n'est montree.
- Le manuscrit le dit deja, mais la conclusion doit rester strictement measurement/protocol-specific.

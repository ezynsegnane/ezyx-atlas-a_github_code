Remarques critiques P0

1. PDF metadata / hyperref toujours problematique
- `main_en.log` contient encore de nombreux warnings hyperref autour de l'abstract.
- `pdfinfo main_en.pdf` montre un champ Subject enorme contenant tout l'abstract avec symboles mal convertis.
- Le champ Author montre encore un mojibake pour Peluffo-Ordonez.
- A corriger avant soumission: PDF strings simples, pas de math dans metadata, encodage auteur propre.

2. DOI Holloway2026 probablement incorrect
- `bibliography.bib` donne `10.1007/978-3-031-87568-3` et note que c'est le DOI volume.
- Les sources externes trouvees pour le chapitre "Evaluation of Raw Signal and Feature-Based Deep Learning Models for Multi-Label ECG Diagnosis on PTB-XL" donnent le DOI chapitre `10.1007/978-3-032-11442-6_36`, pages 458-464.
- Corriger vers le DOI chapitre ou justifier explicitement pourquoi le DOI volume est utilise.

3. Pre-declaration: preuve publique incomplete dans le manuscrit
- Le repo public contient `analysis_plan.md`; son SHA-256 est `4ad22e907fbd431a0b443255a3449c0560371997d5ee36a61e164de7aea5c3dc`.
- Les JSON de runs contiennent ce meme `analysis_plan_sha256`, ce qui soutient la provenance.
- Mais le manuscrit ne cite pas ce hash ni un commit/tag public.
- Les JSON de run citent `git_sha = b8fda1f7...`; ce commit est present dans le repo local/worktree, mais pas dans l'historique public GitHub clone actuel. Un reviewer externe ne peut donc pas verifier directement le code exact.
- Action: pousser/tagger l'historique contenant b8fda ou fournir une archive immuable, puis citer commit + SHA dans Data Availability.

4. Group F est encore trop fort
- Le manuscrit l'appelle encore "confirmatory generalisation check".
- Group F teste seulement `demo+anthro` sur quatre folds alternatifs, 5 seeds chacun.
- Il ne teste pas `none` et `demo` sur ces folds; il ne prouve donc pas que les gains metadata generalisent.
- Les val folds changent avec les test folds; le gap peut venir du test fold, du validation fold ou de la selection de checkpoint.
- Action: remplacer par "multi-split absolute-performance check" et ecrire "fold 10 was lower than the four tested alternative demo+anthro folds".

5. Patient-level predictions non archivees
- Le manuscrit dit que patient-level probability arrays were not archived.
- Cela limite DeLong, calibration, decision curves, subgroup fairness, patient bootstrap, threshold verification et reanalysis independante.
- Si possible, archiver les predictions par `ecg_id`, seed, variant et classe. Sinon, mettre cette limite plus haut dans Limitations.

Remarques majeures P1

6. Wilcoxon exact pas assez specifie
- Le manuscrit ne donne pas zero_method, ties, SciPy version, ni fallback exact/approx.
- Le plan public a une regle, mais elle doit etre dans le manuscrit ou Table S1.
- Les p-values sont parfois `approx` ou `<`. Pour un papier de statistique/reproductibilite, fournir p_raw exacts et p_BH exacts en supplement.

7. Langage exploratoire encore parfois trop fort
- L102: "Group E ... confirm that the ECG signal is indispensable" est trop fort.
- L388: "not a neutral design choice" pour Group D reste trop ferme pour une analyse exploratoire non corrigee.
- L391/L414: "confirms" pour E1/F reste attaquable.
- Action: utiliser "suggest", "show under this design", "nominally significant exploratory result", "consistent with".

8. Architecture narrative vs resultats
- Le manuscrit met beaucoup en avant "quality-gated" et GLU.
- Or q_meta sature a 1 avec age/sex, et Group E montre que le gate/fusion mechanism n'est pas necessaire pour la macro-AUC.
- Action: presenter EZNX-ATLAS-A comme instrument de mesure; ne pas vendre le gate comme innovation causale.

9. Group F et benchmark Strodthoff
- L338 dit que Group F montre que fold 10 est "harder than average". Le design ne teste pas la moyenne des 10 folds, seulement 4 folds alternatifs et demo+anthro.
- Action: "lower than the four tested alternative folds" au lieu de "harder than average".

10. Label protocol
- Le manuscrit affirme que no likelihood threshold est coherent avec le benchmark superdiagnostic.
- C'est plausible, mais un reviewer peut demander une preuve.
- Action: ajouter une verification de label counts ou un script de comparaison au protocole Strodthoff.

11. Missingness
- L'ancienne incoherence n=10/n=20 est corrigee.
- Limite restante: independent masking of height/weight/BMI est un stress test MCAR non physiologique puisque BMI derive de height/weight.
- Action: garder "synthetic MCAR stress test" partout ou "graceful degradation" est mentionne.

12. Supplementary / artifacts placement
- Le repo public racine contient 250 JSON et les scripts complets.
- Mais `MDPI_template_ACS_v2/artifacts` local/public est vide.
- Action: clarifier que les artifacts sont dans `results/` du depot public, pas dans le dossier v2. Option plus robuste: copier les artifacts essentiels dans le package de soumission.
